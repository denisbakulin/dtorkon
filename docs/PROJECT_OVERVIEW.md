# PROJECT_OVERVIEW

## Что это за проект

`dtorkon` — мини-блог для одного автора. У проекта две основные поверхности:

- публичная витрина с лентой публикаций и страницами статей;
- приватная авторская админка, где автор пишет статьи, загружает media, прикрепляет файлы, настраивает контакты сайта и смотрит внутреннюю аналитику.

## Поверхности

### Публичный сайт

- доступен на основном домене;
- включает `/`, `/blog`, `/posts/:slug`, `/contact`;
- не показывает кнопку или явную ссылку на админку;
- поддерживает поиск `q` по публикациям.

### Авторская админка

- production-вход живет на `admin.denisbakulin.ru`;
- локально может открываться через `localhost` и путь `/admin`;
- использует admin-only login по cookie session;
- содержит overview, редактор постов, upload flow, site profile и analytics.

## Роли

### Читатель

- открывает главную страницу;
- переходит в блог или связь;
- читает опубликованные статьи;
- открывает изображения и файлы во вложениях;
- может слушать аудио и смотреть видео во вложениях.

### Автор

- логинится в закрытую админку;
- создает и редактирует статьи;
- загружает cover, tracked inline media и файлы;
- собирает attachments block;
- публикует материалы;
- редактирует контакты и публичные author-данные;
- смотрит аналитику по постам и assets.

## MVP-границы

В MVP входят:

- один автор;
- cookie-based авторизация;
- SQLite для постов, сессий и metadata;
- Yandex Object Storage для изображений, файлов, аудио и видео;
- markdown как канонический формат статьи;
- public search по `q`;
- кастомные media players;
- image editor перед image upload;
- транскрибация audio/video через Groq;
- внутренняя admin analytics панель.

В MVP не входят:

- Telegram auth;
- пользовательские профили;
- комментарии;
- multi-user роли;
- scheduled publishing;
- полноценная media library вне редакторского сценария.

## Контентная модель

Статья состоит из:

- заголовка;
- `slug`;
- `excerpt`;
- markdown-тела;
- необязательной обложки;
- набора прикрепленных элементов внизу статьи.

Media делятся на:

- `cover`;
- `inline media`;
- `attachments block` с файлами, аудио и видео.

Inline media хранится в `body_markdown`, но backend отдельно отслеживает связанные assets, чтобы их нельзя было удалить как неиспользуемые.
