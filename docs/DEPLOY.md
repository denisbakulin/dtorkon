# Deploy Notes

## Что уже настроено

- фронтенд собирается внутри `infra/nginx/Dockerfile`;
- Nginx отдает содержимое `dist` как обычную статику;
- сертификаты читаются из `/etc/letsencrypt/live/<domain>/`;
- при обновлении файлов сертификатов контейнер Nginx делает `reload`;
- certbot вынесен в отдельный сервис и сам пытается выпустить сертификат, а затем продлевает его по циклу.

## Подготовка

1. Скопируйте `.env.example` в `.env`.
2. Укажите:
   - `DOMAIN_NAME=ваш-домен`
   - `LETSENCRYPT_EMAIL=ваша-почта`
3. Убедитесь, что DNS-записи в Cloudflare уже смотрят на IP сервера.

## Первый запуск

```bash
docker compose up -d --build
```

На первом старте, пока настоящего сертификата нет, Nginx поднимется с временным self-signed сертификатом. Это нужно, чтобы сайт уже отдавался, а HTTP challenge от Let's Encrypt был доступен.

Если домен уже указывает на сервер и `LETSENCRYPT_EMAIL` заполнен, сервис `certbot` сам попробует выпустить сертификат для `DOMAIN_NAME`.

Если позже понадобится и `www`, это можно будет добавить отдельной переменной или вторым доменом в certbot-команду.

Если DNS ещё не доехал, первая попытка не пройдет — это нормально. Контейнер продолжит повторять цикл, а ускорить новую попытку можно так:

```bash
docker compose restart certbot
```

## Продление

- сервис `certbot` регулярно выполняет цикл issue/renew;
- Nginx отслеживает изменения сертификатных файлов и делает `reload`;
- интервал проверки можно менять через `CERT_CHECK_INTERVAL`.
